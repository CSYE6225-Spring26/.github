## Overview

A production-grade cloud-native application deployed across two isolated AWS environments (**DEV** and **DEMO**) using fully automated CI/CD pipelines. The system is built around immutable infrastructure — every code change triggers an AMI rebuild, a new Launch Template version, and a rolling instance refresh with zero manual intervention.

## Features

- **RESTful API** — user registration, authentication, product management, and email verification
- **Immutable deployments** — Packer builds a new AMI on every merge; instances are never updated in-place
- **End-to-end encryption** — four dedicated KMS keys (EBS, RDS, S3, Secrets Manager), all with 90-day automatic rotation
- **Serverless email verification** — SNS → Lambda → DynamoDB → SendGrid flow triggered on user registration
- **Auto Scaling** — EC2 instances spread across 3 Availability Zones behind an ALB, with CPU-based scale-out/in policies
- **Secrets management** — DB credentials auto-generated by Terraform and stored in Secrets Manager; retrieved at boot via AWS CLI
- **Observability** — structured JSON logs and custom metrics shipped to CloudWatch via the CloudWatch Agent

## Deployment

Deployments are fully automated via GitHub Actions — merging a PR is the only manual step required.

**webapp** — on merge to `main`:
1. Builds the Spring Boot JAR
2. Runs Packer to build a new AMI in DEV, shared automatically to DEMO
3. Creates a new Launch Template version in DEMO with the new AMI
4. Triggers an instance refresh on the DEMO Auto Scaling Group and waits for completion

**serverless** — on merge to `main`:
1. Builds the Lambda fat JAR
2. Deploys to the DEV Lambda function
3. Deploys to the DEMO Lambda function

**tf-infra** — on every PR:
1. Runs `terraform fmt -check`, `terraform init`, and `terraform validate` for AWS

## Improvements

- **Move EC2 instances to private subnets** — currently the ASG runs in public subnets; placing instances behind the ALB in private subnets would eliminate direct internet exposure
- **Add WAF rules** — the WAF resource is provisioned but rule sets (rate limiting, SQL injection, XSS) are not yet attached to the ALB
- **Lambda deployment via S3 versioning** — currently the CI pipeline uploads the JAR directly; using S3 versioned artifacts would enable easier rollbacks
- **Separate KMS keys per environment** — DEV and DEMO share key aliases by `name_prefix`; dedicated keys per account would improve blast-radius isolation
- **Add integration tests to the serverless pipeline** — the Lambda CI only validates compilation; end-to-end SNS → DynamoDB tests would catch regressions earlier
